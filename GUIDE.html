Understanding & Running EVALON

A step-by-step guide to set up, run, and demo the AI-powered hackathon evaluation engine — no prior experience needed.

🤔 What is EVALON?

Imagine you're running a coding competition (hackathon) with 50 participants. Each person submits a GitHub link to their project. Normally, a panel of judges would have to manually look at every project, read the code, and give scores. That takes days and is very inconsistent.

EVALON automates this entire process. You give it a GitHub link, and within ~3 minutes it:

📥

Downloads the code

Clones the GitHub repository to analyze it safely

🔬

Analyzes it

Measures code complexity, style, documentation quality

🤖

AI reviews it

3 specialized AI agents evaluate different aspects

📊

Generates a report

Detailed scorecard with specific evidence and feedback

💡
Key principle

EVALON never just makes up scores. Every number comes from real code measurements. The AI only interprets those measurements — it doesn't invent them.

Who uses it?

Role What they do What they see
Admin Creates hackathons, sets judging criteria, finalizes rankings All submissions, all scores, admin dashboard
Participant Joins hackathons, submits GitHub repos, chats with AI mentor Their own evaluation report, leaderboard (after finalization)

⚙️ How It Works (Simple Version)

Think of EVALON as a factory with different stations. When you submit a GitHub link, it goes through these stations one by one:

🔗 Stage 1: Clone Repository
Downloads your GitHub project to a temporary folder. Like pressing "Download ZIP" but automatic.
📁 Stage 2: Analyze Files
Counts files, detects programming languages, reads README, measures code complexity using specialized tools (radon, ESLint).
🤖 Stage 3: AI Evaluation (3 agents)
Three different AI personas each evaluate one thing:
• Agent 1: "What is this project? Is it well explained?"
• Agent 2: "Is the code written well? Any bad patterns?"
• Agent 3: "Is this idea creative? Is the solution impressive?"
📊 Stage 4: Score & Report
Combines all agent scores using the weights you set (e.g., Code Quality = 40%, Innovation = 35%). Generates a detailed written report.
🧠 Stage 5: Build Memory (Embeddings)
Creates a searchable "memory" of the project so the AI Mentor chatbot can answer specific questions about the code.
🔒
Important: No code is ever executed

EVALON only reads files as text. It never runs your code, npm install, pip install, or any scripts. It's completely safe.

Before you can run EVALON, you need two things installed on your computer:

The SECRET_KEY is used to sign login tokens. If you leave the default value, the app will still work for demo purposes — but never use a default secret in a real deployment.

Everything else in .env can stay as default for local development.

🚀 Step 3: Start All Services

One command starts everything — the database, the AI engine, the web server, and the frontend:

Terminal — run this once 
make up
# Or if make doesn't work:
docker compose up -d
⏳
First time takes 10–20 minutes

Docker needs to download the AI models (about 5 GB total). This only happens once. Subsequent starts take under 30 seconds.

What's happening behind the scenes?

Docker starts 7 mini-computers (called "containers"), each running one part of EVALON:

Container What it does Like...
hackeval_postgres Stores all data (users, hackathons, scores) A filing cabinet
hackeval_redis Manages the job queue and real-time events A post office
hackeval_ollama Runs the AI language models locally The AI brain
hackeval_backend The main API server (handles all requests) The manager
hackeval_worker Runs evaluation jobs in the background The lab assistant
hackeval_frontend The website you see in the browser The storefront
hackeval_nginx Routes traffic to the right container A receptionist

Check that everything started

Terminal 
docker compose ps
# You should see all 7 containers with "running" or "healthy" status
✅
Quick health check

🏗️ Architecture — How the Pieces Connect

Here's a simplified view of how the 7 services communicate:

Your Browser → Nginx (Port 80)
↙ /api/* routes here     ↘ /* routes here
FastAPI Backend            Next.js Frontend
Backend connects to:
PostgreSQL & Redis
Redis queue sends jobs to:
ARQ Worker
Worker calls:
Ollama (AI Models) and PostgreSQL

The Evaluation Flow in Detail

  1. You click "Submit" in the browser
  2. Browser sends request to FastAPI → creates a submission record in PostgreSQL
  3. FastAPI drops a job message into Redis ("evaluate submission X")
  4. FastAPI immediately returns "Submitted! ✓" to the browser — it doesn't wait for the AI
  5. The browser opens an SSE connection to poll for updates
  6. The ARQ Worker picks up the job from Redis
  7. Worker runs the LangGraph pipeline: clone → analyze → AI agents → score
  8. Worker calls Ollama (AI models) 3 times, one per agent
  9. Worker saves all results to PostgreSQL
  10. FastAPI detects the completed status → SSE sends "completed" event to browser
  11. Browser shows the evaluation report
💡
Why a separate Worker?

AI evaluation takes 2–4 minutes. If the backend waited during that time, you couldn't use the website at all. By using a separate worker with a queue, the website stays fast and responsive while evaluations happen in the background.

🤖 AI Agents Explained

EVALON uses 3 specialized AI personas, each with a different job:

Agent 1: Repository Understanding Agent

Persona: "I'm a tech journalist reviewing this project."

It asks: What problem does this solve? Who is it for? Is the purpose explained clearly in the README? Does the file structure make sense?

Input: README content, file tree, dependency list

Output: Score 0–10 + evidence about documentation quality

Agent 2: Code Quality Agent

Persona: "I'm a senior engineer doing a code review."

Important: This agent does NOT guess at code quality. It receives the actual numbers from static analysis tools, then interprets them:

  • radon measures: cyclomatic complexity (how tangled the code is), maintainability index
  • ESLint measures: JavaScript/TypeScript style violations
  • semgrep finds: security vulnerabilities, bad patterns

The AI then says "12 functions have complexity > 10, which indicates potential for bugs" — based on real numbers, not guesses.

Output: Score 0–10 + list of specific findings with file references

Agent 3: Innovation Agent

Persona: "I'm a VC evaluating whether this is worth funding."

It asks: Is this problem interesting? Is the solution creative or just a tutorial clone? Does it use interesting technology? Does it feel complete?

Calibration: The agent is explicitly told: "A score of 5 = a competent but boring CRUD app. 7+ = genuine creativity. 9+ = something that would impress a senior engineer."

Output: Score 0–10 + reasoning about novelty and sophistication

How scores become the final grade

With the default hackathon criteria (Code Quality 40%, Innovation 35%, Project Understanding 25%):

Score calculation example
# Agent scores (example):
repo_understanding_score = 8.0
code_quality_score       = 6.5
innovation_score         = 7.2

# Weighted average:
final = (8.0 × 0.25) + (6.5 × 0.40) + (7.2 × 0.35)
final = 2.0  +  2.6  +  2.52
final = 7.12  # → Grade: B+

🔧 Troubleshooting Common Issues

Problem: "make up" fails or containers don't start

❌
Symptom

You see error messages when running make up, or some containers show "Exit" status.

Solution:

Terminal 
docker compose logs --tail=50
# Read the error messages to see which container failed and why

Most common cause: Docker Desktop doesn't have enough memory. Go to Docker Desktop → Settings → Resources → Memory → set to 8 GB.

Problem: Ollama models take forever / evaluation never starts

⏳
Symptom

You submitted a repo but it stays on "pending" for more than 5 minutes.

Check if Ollama is still downloading:

Terminal 
docker compose logs ollama --tail=30
# Look for "pulling..." messages — models are still downloading
# This is normal on first run, wait for it to complete

Problem: Health check shows Ollama as "unhealthy"

Terminal 
docker compose logs ollama | grep -E "pulling|success|error"

If models haven't been pulled yet, run:

Terminal 
docker compose exec ollama ollama pull nomic-embed-text
docker compose exec ollama ollama pull qwen2.5:7b
docker compose exec ollama ollama pull qwen2.5-coder:7b

Problem: "make" command not found (Windows)

On Windows, use the Docker commands directly instead:

Instead of make commands, use:
# Instead of: make up
docker compose up -d

# Instead of: make migrate
docker compose exec backend alembic upgrade head

# Instead of: make seed
docker compose exec backend python -m app.scripts.seed

# Instead of: make logs
docker compose logs -f

Problem: Frontend shows "502 Bad Gateway"

The backend isn't ready yet. Wait 30 seconds and refresh. If it persists:

Terminal 
docker compose logs backend --tail=20

Problem: Want to start fresh (reset everything)

⚠️
This deletes all data

The command below removes all containers AND all stored data (users, hackathons, evaluations). Ollama models are kept to avoid re-downloading.

Terminal — nuclear reset 
docker compose down -v  # stops everything and deletes data volumes
docker compose up -d    # start fresh
make migrate             # recreate database tables
make seed                # recreate demo accounts

Useful monitoring commands

Terminal — helpful commands 
# See what's running
docker compose ps

# Follow all logs live
make logs

# Follow only the worker (where evaluations happen)
docker compose logs -f worker

make shell
